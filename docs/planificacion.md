# Cronograma

| Semana | Hito | Responsable(s) |
|---|---|---|
| S1–S2 | Institución elegida; requisitos RF/RNF, restricciones y criterios de éxito | Integrante 1 (Requisitos/Doc.) |
| S3 | Cronograma, roles y comparación de paradigmas cerrados | Todo el equipo |
| S4 | Prototipo de viabilidad (integración multiparadigma) ejecutado, con veredicto | Integrante 3 (Dev.) |
| S5 | Diagnóstico de riesgos y primer ciclo de retroalimentación documentado | Integrante 5 (QA) |
| S6 | Entrega EP (avance) | Todo el equipo |
| S6–S7 | Diagrama de clases UML completo y patrones de diseño | Integrante 2 (Arquitectura) |
| S7 | Implementación completa (todos los RF/RNF) y pruebas automatizadas | Integrantes 3 y 4 (Dev.) |
| S8 | Informe consolidado, ensayo de sustentación y entrega EF | Todo el equipo |

# Roles diferenciados

- Integrante 1 — Levantamiento de requisitos y redacción/consolidación del informe.
- Integrante 2 — Arquitectura del sistema y modelado UML.
- Integrante 3 — Desarrollo backend (integración POO + programación funcional).
- Integrante 4 — Desarrollo de la interfaz orientada a eventos e integración general.
- Integrante 5 — Control de versiones (Git), pruebas automatizadas y calidad de código.

# Dependencias y contingencia

- El diagrama UML (S6–S7) depende de que los requisitos y la selección de
  paradigmas (S1–S3) estén cerrados.
- La implementación completa (S7) depende del UML aprobado y del veredicto
  del prototipo de viabilidad (S4).
- Contingencia: si la interfaz orientada a eventos resulta muy costosa en
  tiempo, se reemplaza por un menú de consola simple.
